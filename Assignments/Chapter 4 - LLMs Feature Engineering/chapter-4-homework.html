Chapter 4 Homework: LLMs for Feature Engineering

Instructions

This homework is meant to be completed with AI assistance (such as an in-browser LLM like ChatGPT, and/or using a CLI like Claude Code) while also making real API calls to a commercial LLM (OpenAI, Anthropic, or Google) for feature extraction. You are building an end-to-end pipeline that turns messy review text into structured features an ML model can actually use.

For all questions, submit:

  1. Your code (in a .py file or Jupyter notebook)
  2. All visualizations, tables, and pipeline outputs
  3. Written answers to interpretation questions (can be in markdown or comments)
  4. The prompts you used — both the prompts you gave to your coding assistant and the prompts you sent to the LLM API from inside your pipeline

API cost and sample size

You will be sending real requests to a paid API. To keep your total spend well under $1:

  • Use a cheap model by default (e.g., gpt-5.4-nano)
  • Never create loops that loop over the data many times.
  • Always test your code on just a few rows, that way you’re not wasting money send the LLM many rows of data for something that doesn’t work.
  • Cache responses so re-running your notebook does not re-bill you
  • Be aware that some reviews in this dataset are thousands of characters long — truncate (e.g., reviews.text[:2000]) or summarize before extraction when token counts matter
  • Check the Slack channel for the API key. This API key will be deleted after the homework due date.

Dataset

Download cleaned_amazon.csv

You’ll be working with a dataset called cleaned_amazon.csv containing Amazon product reviews. The dataset includes:

  • name: Product name (e.g., “Kindle Paperwhite”, “Amazon Echo Dot Case - Indigo Fabric”, “Fire HD 7 Tablet”)
  • reviews.numHelpful: Count of “helpful” votes on the review (mostly 0, with a long tail)
  • reviews.rating: Star rating from 1–5. Many rows are missing this field — you will use the labeled subset as ground truth
  • reviews.text: The review body. Lengths range from ~10 words to multi-thousand-word essays
  • reviews.title: The review title
  • price: Product price in USD

A few characteristics you should be aware of before you start:

  • The dataset contains duplicate review text across color/variant listings of the same product (e.g., Echo Dot cases). This matters for caching.
  • Reviews span several product families (e-readers, tablets, streaming devices, accessories), which makes category extraction interesting.
  • Questions 8–10 require rows where reviews.rating is not null — filter accordingly in those questions.

Questions

Question 1 (5 points)

Write code that connects to your chosen LLM API and extracts the sentiment (positive, negative, or neutral) from the first 20 rows of cleaned_amazon.csv. For each row, send reviews.text (truncated to 2000 characters if needed) to the model with a simple classification prompt.

Display the results as a DataFrame with three columns: name, a truncated preview of reviews.text (first 120 characters), and the extracted sentiment.

Deliverables:

  • The prompt(s) you used (both the coding-assistant prompt and the LLM API prompt)
  • The code
  • The resulting DataFrame (as a table in your notebook or a saved CSV)
  • 2–3 sentences: did the extracted sentiment match your intuition from reading a few reviews by hand?

Question 2 (5 points)

Write three different prompt variants that extract a product_category label from each review. The allowed categories are: e-reader, tablet, streaming_device, accessory, and other.

The three variants should differ in a meaningful way — for example:

  • Variant A: zero-shot (see the textbook for details), minimal instructions
  • Variant B: zero-shot, with an explicit category definition for each label
  • Variant C: few-shot (see the textbook for details), including 2–3 worked examples in the prompt

Run each variant on the same 15 rows (pick rows that span multiple product families). Compute the pairwise agreement rate between the three variants (i.e., for how many rows did all three variants agree?).

Deliverables:

  • The three prompt variants you used
  • The code that runs all three and tabulates the results
  • A table showing, for each row, the label assigned by each variant
  • Your written interpretation (3–4 sentences): which variant produced the most consistent labels, and why do you think so?

Question 3 (5 points)

Design a single prompt that extracts four fields at once as JSON from a review:

  • sentiment: one of positive, negative, neutral
  • aspect_mentioned: one of battery, screen, price, build_quality, other
  • issue_reported: boolean — did the reviewer report a defect or problem?
  • recommended: boolean — did the reviewer recommend the product?

Run this on 25 rows of cleaned_amazon.csv. Parse each response into a Python dict, then assemble the parsed results into a DataFrame.

Deliverables:

  • The prompt you used
  • The code (including how you parsed the JSON)
  • The resulting DataFrame (25 rows × 4 extracted columns)
  • 2–3 sentences: how often did the model’s issue_reported = True label line up with a low reviews.rating on the same row?

Question 4 (6 points)

Extend your Q3 pipeline with a validation layer. For each raw model response, your validator must check:

  1. The response parses as JSON
  2. All four required keys are present
  3. Each value is in the allowed set (e.g., sentiment is exactly one of the three allowed strings; issue_reported and recommended are True/False)

Run your validated pipeline on 50 rows chosen to include both very long reviews (len(reviews.text) > 2000) and very short reviews (len(reviews.text) < 50). Log every failure and report the overall failure rate, broken down by review length.

Deliverables:

  • The prompt(s) and validator code
  • A table of failure counts by category (parse failure / missing key / bad value) and by review length bucket
  • Written interpretation (4–5 sentences): do long or short reviews fail more often? What kinds of failures dominate, and what does that suggest about your prompt?

Question 5 (6 points)

Using your code from from Q4, write a cost analysis report. You must:

  • Count the number of words sent and received
  • Multiply this by 1.3 (as each word is roughly equal to 1.3 tokens)
  • Compute the total dollars spent at your model’s published per-token price (Google to see pricing for gpt-5.4-nano)
  • Estimate the average cost per 100 reviews

Deliverables:

  • The prompt(s) you used
  • The cost-analysis code and the resulting tables
  • A bar chart or similar visualization of cost by length bucket
  • Written interpretation (4–5 sentences): is upgrading to the expensive model worth the extra cost for this task, or not? Justify based on both cost and any accuracy differences you observed.

Question 6 (5 points)

Take the extracted four-field features from Q5 and convert them into an ML-ready feature matrix X:

  • One-hot encode sentiment (3 columns) and aspect_mentioned (5 columns)
  • Keep issue_reported and recommended as boolean (0/1) columns
  • Join back to the original row so that X is aligned with name, reviews.numHelpful, reviews.rating, and price

Report the shape of X, the data types of each column, and print the first 5 rows.

Deliverables:

  • The prompt(s) you used
  • The feature-engineering code
  • The shape, dtypes, and head of the resulting feature matrix
  • 2–3 sentences: which columns of X do you expect to be most predictive of reviews.rating, and why?

Question 7 (6 points)

Build a keyword-based baseline that does not call the LLM. Specifically:

  • Write a simple sentiment classifier using positive and negative word lists (e.g., “love”, “great”, “broken”, “disappointed”)
  • Write a simple category classifier using keyword matches on name and reviews.text (e.g., “kindle” → e-reader, “case” → accessory)

On the subset of rows where reviews.rating is not null, compare your keyword baseline against the LLM output using reviews.rating as ground truth (≥4 → positive, ≤2 → negative, 3 → neutral). Report:

  • Accuracy for each approach, for both sentiment and category
  • Per-record cost for LLM (from Q6) vs. zero for the keyword baseline

Deliverables:

  • The prompt(s) you used
  • The keyword baseline code
  • An accuracy and cost comparison table
  • Written interpretation (4–5 sentences): when is the keyword baseline “good enough”? Recommend a hybrid strategy — which kinds of rows should you route to the LLM and which to the keyword baseline?

Question 8 (6 points)

Pick 20 reviews from the rating-labeled subset and manually label each one yourself for sentiment and product_category. Then:

  • Compare your hand labels to the LLM’s labels on those same 20 rows
  • Compute LLM accuracy against your hand labels
  • Analyze the errors: do the LLM mistakes cluster around long technical reviews? Reviews with mixed sentiment (e.g., “I love the hardware but the software is broken”)? Sarcasm?
  • Based on the error patterns, propose one concrete prompt improvement, rerun those 20 rows with the improved prompt, and report whether accuracy improved.

Deliverables:

  • The prompt(s) you used (original and improved)
  • Your 20 hand labels, alongside the original LLM labels and the improved LLM labels
  • Written interpretation (5–6 sentences): what kind of errors did the LLM make? What did your prompt improvement target, and did it help?

Question 9 (7 points)

Build an end-to-end capstone pipeline on the subset of rows where reviews.rating is not null:

  1. Use your Q5 pipeline to extract the four-field features from reviews.text
  2. Build two feature matrices:
    • Model A (LLM features): one-hot sentiment + one-hot aspect_mentioned + issue_reported + recommended
    • Model B (no-LLM baseline): len(reviews.text) + reviews.numHelpful + one-hot name
  3. Define your target y: 1 if reviews.rating >= 4, else 0
  4. 80/20 train/test split, train a classifier of your choice (e.g., logistic regression, random forest) on each feature matrix
  5. Report accuracy, a confusion matrix, and the top feature importances for each model

Then write a 1-page executive summary (300–400 words) aimed at a stakeholder with no ML background. Explain:

  • What the pipeline does end-to-end
  • How well Model A (LLM features) performed vs. Model B (no-LLM baseline)
  • What the LLM-extracted features added — or failed to add — to the prediction
  • Realistic cost considerations at production scale (use your Q6 extrapolation)
  • Recommendations for what you’d try next

Deliverables:

  • The prompt(s) you used
  • The full pipeline code and all evaluation outputs (accuracy, confusion matrices, feature importances)
  • Your 300–400-word executive summary
  • Reflection: how did having LLM-extracted features change what was possible in this classification task compared to using only traditional tabular features?

Submission Guidelines

Submit a ZIP file containing one folder for each problem. Within each folder you should have one file for each of the following:

  1. Code files: All .py files or Jupyter notebooks
  2. Outputs folder: All tables, cached API responses, and visualizations generated
  3. Written responses: A single document (PDF or Markdown) with all your written answers, interpretations, and AI prompts used
  4. Data: Include your cached extracted features or any modified datasets you created

Tips for Success

  • Write specific, detailed prompts — both to your coding assistant and to the extraction LLM
  • If the extraction LLM’s first prompt isn’t producing clean JSON, refine it; do not silently patch bad output
  • Always review and test the AI-generated code
  • Don’t just accept AI output — understand what it’s doing
  • Include context in your prompts (e.g., “I’m extracting four fields from Amazon product reviews; output only valid JSON with these exact keys…”)

General:

  • Start early — hitting a real API introduces flaky network behavior that takes time to handle
  • Cache aggressively so a failed re-run doesn’t cost you money twice
  • Your interpretations are just as important as your code
  • When the LLM makes a weird extraction, look at the actual review — it often teaches you something
  • Use your brain. That’s what it’s there for.
